# Font Sketch

Find Google Fonts by the shape of a single character: draw it, or pick a font and find fonts where that character looks similar.

Shape search compares center-line geometry. Hand-drawn queries also compare stroke ends extracted separately from the rendered glyph, because pruning a medial axis can remove a short but meaningful stem.

## Pipeline

1. `npm run download`: downloads a subset (a–z, A–Z, 0–9, `ä ö ü ß Ä Ö Ü` and `& @ ? ! # $ % + * { } § " €`, see `src/chars.js`) of every Latin Google Fonts family at weight 400 into `data/fonts/`. `--refresh` downloads the files of the families in `data/manifest.json` again and keeps the manifest (for new characters: then run `node scripts/build-index.mjs '<new characters>'`, `node scripts/build-topology.mjs '<new characters>'`, `node scripts/embed.mjs '<new characters>' --skeleton` and `python3 scripts/pack-embeddings.py '<new characters>'`; `npm run index -- '<chars>'` passes the characters only to the last of its two scripts).
2. `npm run index`: shapes each character with HarfBuzz (so default OpenType features like small caps in "Anton SC" apply, as in the browser) and computes its skeleton as curves: the medial axis (`scripts/medial.mjs`). The outline is flattened and sampled densely, the Voronoi vertices of the samples inside the glyph (a raster mask does the inside test, so overlapping contours are fine) approximate the medial axis, and the ends are cleaned up: the axis is trimmed while its radius grows faster than 0.35 per unit of length (the signature of a corner wider than about 40°; pointed strokes and script tails grow slower and stay) and is still below 92% of the stroke's own radius (the median along the line, so a short stem keeps poking out of a bowl); what is left of a corner branch at a junction goes when it is shorter than 0.9 times the half stroke width there; and each free end is cut back by one radius and carried on straight, in the direction the axis had before, to the outline, so a stroke ends in the middle of its end, not where the last inscribed disk sits. The polylines are fitted into a 64×64 frame and written with quarter-cell precision, one binary file per character, to `public/data/g/`. A glyph whose medial axis fails falls back to raster thinning (Zhang-Suen). Takes about 6 minutes. It also runs `scripts/build-topology.mjs`, which rasterizes the same glyphs, thins them without medial-axis branch pruning, and saves stroke ends to `public/data/t/`. Run `npm run index-topology` to rebuild just these descriptors.
3. `node scripts/embed.mjs --skeleton`: draws each skeleton with a fixed stroke width and computes DINOv2 features (CLS token and a 4×4 grid of patch tokens) into `data/emb-skel/`. Takes about 3 minutes per character on a CPU. `--only=Family,Family` computes only these families and writes their rows into the existing files.
4. `python3 scripts/pack-embeddings.py`: reduces the 4×4 grid features with PCA to 256 dimensions, quantizes them to int8 and writes `public/data/e/` (about 470 KB per character).
5. `node scripts/embed-style.mjs` and `python3 scripts/pack-style.py`: one "style" vector per font for its overall look (filled glyphs of a two-line specimen, so weight, width, contrast and decoration count). Writes `public/data/style.bin` (128 int8 values per font). Takes about 3 minutes.
6. `node scripts/download-variants.mjs` and `node scripts/measure.mjs`: downloads a tiny subset of every variant (weight × italic, about 7,500 files) and measures weight and slant per variant, and x-height, serifs, straightness, width, contrast and stroke ends (round/sharp) per family. `--keep-variants` measures only the family values again. Writes `public/data/metrics.json` from scratch, so run steps 7–13 again afterwards. Takes about 3 minutes.
7. `python3 scripts/measure-width.py`: for fonts with a wdth axis, downloads the variable WOFF2 (the CSS API sends variable fonts only to browsers, so it uses a browser User-Agent), makes static instances along the axis with fontTools and measures the real width there. The wdth axis changes the width very differently per font (Roboto Flex at wdth 25 is only 15% narrower than at 100). Needs `pip install brotli`.
8. `node scripts/caps.mjs`: marks fonts without real lowercase letters (caps-only fonts and fonts with small capitals as lowercase) with `lc: 0` in `metrics.json`. For 9 letters (a, b, d, e, g, h, n, q, r), it checks if the lowercase skeleton looks more like the font's own capital than like the lowercase form of some popular fonts. A search for a lowercase character skips these fonts.
9. `node scripts/ornate.mjs`: how ornate (flourished) each font is, `o` in `metrics.json` (0 = plain, 1 = very ornate). Flourishes reach beyond the space of a letter, so it measures the overhang: ink left of the origin, right of the advance width and below the baseline, in x-heights, averaged over 19 letters (from the outline bounding boxes), on a log scale. Takes a few seconds.
10. `node scripts/form.mjs`: letter-form values in `metrics.json`: aperture (angle in which one sees out of the counters of c and e), roundness of o and O (variation of the distance of the outline from the center), extenders (ascender above the x-height plus descender, in x-heights), serif type (serif thickness divided by the stem width, hairline to slab; only with serifs) fixed width (variation of the advance widths of a–z), and stroke fill (`hf`, hollow stems versus solid strokes). Takes about 30 seconds. `node scripts/form.mjs <family> …` only prints the values. `node scripts/stroke-fill.mjs` rebuilds only stroke fill; named families print their measurements.
11. `node scripts/connected.mjs`: how connected the lowercase letters are, `cn` in `metrics.json` (0 = all separate, 1 = every pair joined, as in connected scripts). Twelve pairs such as "an" and "ou" are shaped with HarfBuzz, both glyphs are rasterized at their positions, and a pair is joined when the ink of the two glyphs overlaps or comes within a hairline (about 1.7% of the em) along at least a few pixels. Fonts without real lowercase letters get no value. Takes about 10 seconds. `node scripts/connected.mjs <family> …` only prints the values.
12. `node scripts/distinct.mjs`: how distinct the letters of each font are, `dx` in `metrics.json`: the mean chamfer distance between the skeletons of 12 letters, divided by the median over all fonts (about 1 for a text face, 0 when all letters look the same). Fonts below 0.2 (placeholders like Flow and Redacted, knitting patterns, keyboard fonts) have no letterforms and stay out of everything; fonts below 0.5 (barcodes, textures, multi-line faces) stay in Browse but out of the shape search, because their skeletons are grids of bars or lines. Takes a few seconds; run it after `npm run index`.
13. `python3 scripts/recognize.py`: letter recognition, `lr` in `metrics.json` (0–1), from the raw skeleton embeddings in `data/emb-skel/` (requires NumPy). Subtracts each font's mean feature vector to remove shared style/texture, then checks whether the five nearest reference glyphs of 12 upper/lowercase pairs represent the same letter (either case). References come from the first 300 fonts by popularity with `dx >= 0.8`, without a font-name list; the query family is excluded. The better of the uppercase/lowercase scores counts, preserving caps-only fonts and scripts with decorative capitals. Below 0.2, a font is excluded throughout the app, including Browse (e.g. Libre Barcode 39 and Yarndings 12). Fewer than six available letters in both cases leaves the value unknown and does not exclude the font. This is a heuristic: barcode captions can contain recognizable letters. Uses the raw features because the packed embeddings use independent PCA coordinates per character. Run after steps 3, 6 and 12; `--dry` lists exclusions without writing, and family arguments only print their scores. Takes about a minute.
14. `python3 scripts/tech.py`: technical statistics from the full font files (the subsets in `data/fonts/` lack most OpenType features): number of glyphs, OpenType feature tags, number of ligatures and variable axis tags, in `public/data/tech.json`. It reads only the table directory and the maxp, fvar, GSUB and GPOS tables of the variable upright file (else the regular static file) with HTTP range requests. Results per family are kept in `data/tech/`. Takes about 10 minutes the first time.
15. `npm run dev`

## Search

- **Sketch:** the query is made of letters: those of the typed name (plus one extra character), each either drawn on the pad or taken from the example font. Click a letter to draw it; "Clear" on a letter without a sketch leaves it out of the query. Letters taken from the example font show their indexed skeletons on the pad, loaded directly rather than from search results; excluded letters keep a dimmed skeleton. Per letter, all fonts are ranked (a sketch by symmetric chamfer distance plus a penalty for extra/missing stroke ends and their positions on the 64×64 grid, the skeleton curves rasterized to the cells they pass through, in a Web Worker; a font glyph by cosine similarity of its packed DINOv2 skeleton features, falling back to chamfer distance where no features are built), the ranks are scaled to 0–1 so that letters compared by different measures weigh the same, and a weighted mean rank orders the fonts. Drawn letters together contribute 80% and letters from the example font together contribute 20%, split equally within each group regardless of text length. With only one group, it contributes 100%. A font needs all query letters.
- **Sketch for any character:** with "any" on the pad, the sketch is compared with all 83 characters. Each font shows its character most like the sketch. A fast pre-check (the glyph-to-sketch direction of the chamfer distance plus the stroke-end penalty) keeps the best 150 fonts per character; these get the full distance. The first search loads all glyph files (35 MB), later searches take about 0.5 s.
- **Groups in the search:** with groups on, a shape search shows only the best font of each group of similar-looking fonts (the same groups as in Browse).
- **Example font:** its glyphs stand in for every query letter that is not drawn. Use "≈" on a card to choose an example and search all fonts by default. Clicking the card itself leaves the query unchanged. Shape results and their group representatives are ordered by similarity; popularity order resumes when the query is cleared.
- **Filters and queries:** Look and Technical show filter results in popularity order. Shape activates the saved drawing or example-font search and orders results by similarity. Switching away pauses Shape without clearing the example, drawings, selected letters or filter preference; returning resumes it. A dim dot marks a saved Shape query. A drawing initially searches within the Look and Technical filters; "≈" searches all fonts by default. "Apply Look filters too" combines either shape query with the current Look and Technical filters, retaining similarity order. With it off, filters do not change the search or its font styles, and filter counts appear struck through only while Shape is active.

## Browse

Type a product name to see it in uppercase, lowercase and as typed. Without custom text, the preview and query letters default to "Abc" (also shown as the input placeholder), so "≈" immediately compares A, b and c. With "Hide look-alikes" on (the default, using a fixed target of 80 groups), the fonts are split into groups of similar-looking fonts (spherical k-means on the style vectors) and only one font per group is shown. Group membership and order stay fixed while filtering: when a representative no longer matches, its replacement takes the same group position. Empty groups disappear without reordering the remaining groups. "≈" on a card searches the fonts whose letters look like its own, see Search. The left pane starts with Explore and Shortlist workspace tabs. In Explore, Look and Technical (the sliders) and Shape (the sketch pad, with the letters of the preview as targets) are accordion sections, with one open at a time. Closing Shape pauses its query without clearing it.

For speed, the groups are computed once for all fonts in a worker (`src/groups-worker.ts`, 40 to 640 groups, about 4 s after load). Filtering only picks the level whose number of groups with passing fonts is nearest to the chosen number (staying at the last level while it fits) and the passing font nearest to each group center, so a slider change takes about 10 ms and the cards stay the same while a slider moves. Variable fonts are loaded once with their whole axis ranges, so other weights and widths only change `font-variation-settings`. A card keeps its old font until the new one has loaded, and while the browser is idle the fonts of the next two fonts of each visible group are loaded ahead (they take over when the representative drops out).

## Font feedback

Hover a font card (or focus one of its buttons) to color the matching existing histogram bar white in the visible sliders. Weight, width and slant follow the displayed style, including interpolation along variable axes; missing measurements leave the histogram unmarked. The markers do not change filters.

The thumbs-down button offers up to three explicitly labeled visual adjustments instead of changing filters immediately. Suggestions favor distinctive ornament, connectedness and other visible letter properties; weight and slant carry less influence, and technical properties are excluded. Ranking combines distance from the current selection's median, the size of the visual difference and the number of retained families. Weak differences produce no recommendation. Shadows and 3D effects are not measured, and the suggestion panel makes that limitation explicit.

Hover or keyboard-focus a suggestion to preview its boundary with a dashed marker. This does not change filters or results; the relevant Look slider is brought into view without pausing an active similarity search. Click to apply, or Cancel/Escape to leave filters unchanged. Suggestions check all reachable styles so a variable font cannot reappear in another variant. Applying highlights the changed slider and shows the excluded count; Undo restores the previous corridors and search-filter preference. Stale suggestions are dismissed when the query or filter selection changes.

## Look sliders

The star at the top right of a font card adds or removes that family from your shortlist. Saved stars stay visible. The Explore and Shortlist tabs switch between discovery and comparison. Shortlist keeps the same split layout: a saved-font list on the left and a specimen desk on the right. Choose a family, edit heading and paragraph text, preview several sizes at once, or pair another saved family for the body. Each font has a style selector, and a swap button exchanges the heading and body fonts. Discovery filters and grouping do not affect specimens. Returning to Explore restores the discovery settings and scroll position. The list is saved in browser storage across reloads. The specimen toolbar links to Google Fonts; Explore cards offer Show similar.

All filters are sliders from measured values; there are no category checkboxes. The look sliders form one continuous list with 36px gaps: weight, width, slant, serifs, serif type while the serifs corridor excludes "none", contrast, ends, straightness, ornate, connected, stroke fill, x-height, circular o, aperture and width variation. Proportion filters are always expanded. They are custom range sliders: drag the ends or the band to set a corridor; double-click sets it back to any. Each slider has two fixed endpoint terms, such as Thin / Heavy or Solid / Outline, with no separate name or changing range caption. Hover or focus either term for the measurement explanation. Current values remain accessible to screen readers. The histogram in each slider shows the fonts that pass all other filters. Fonts without a value for an active slider (for example the serif type of a sans serif) do not pass it. The extenders value is measured but has no slider (it mirrors the x-height). Width variation measures the standard deviation of the advance widths of a–z divided by their mean, from equal (monospaced) to varied, with extra slider space for the typical proportional-font range of 20–32%. Weight, width and slant choose the style to show per family: a named instance, or exact values on the wght, wdth and slnt axes of variable fonts (axes come from the Google Fonts metadata via `download.mjs`). Below each look slider, a sample letter in a font near each end is shown (at most 0.3 and at least 0.7 on the slider); hovering it names the end and the font. The pair is chosen from the metrics when the page loads: far apart on this slider, as alike as possible in all other sliders and in the style vector, and usual and popular (first among the 250 most popular fonts, then 400 and 600 if they have no pair; stroke fill can use the full collection because outline fonts are uncommon). Where a family has the range itself, the pair is often one family (Work Sans 100 and 900, Newsreader and its italic). Below the look sliders, the technical sliders filter by what a font contains: glyphs, OpenType features, ligatures, variable axes (left end at 1 for variable fonts only) and styles. The name of a variable font on its card lists its axes. When fewer than 10 fonts match, the page suggests the smallest corridor changes that bring more fonts back.

Stroke fill samples horizontal sections through the middle of I, l, E, F, L and T. It measures gaps between paired ink edges, discounts asymmetric edge widths and gaps across whole swashes, and combines multiple letters to reduce false matches from script loops. This detects broken outlines without requiring closed counters. Values are family-level heuristics; suggestions require a strong score before proposing More solid strokes.

## Code

Color fonts are always excluded from browsing and shape searches. They are detected from the COLR, SVG, CBDT or sbix tables and recorded as `c` in `tech.json`. Run `python3 scripts/tech.py` to update older caches using the local font files.

Preact with signals, built with Vite, in TypeScript (`npm run check` runs `tsc`; `npm test` checks real-font shape regressions using the generated index). The scripts in `scripts/` are plain Node modules; `src/shape.js` and `src/chars.js` stay JavaScript because both the scripts and the app use them.

- `src/data.ts`: loads fonts, metrics, ligatures and style vectors.
- `src/sliders.ts`: the slider definitions (scales, names, tooltips, sample letters), look and technical.
- `src/filter.ts`: filtering by the sliders, the style to show per family, compromise suggestions.
- `src/groups.ts` and `src/groups-worker.ts`: groups of similar-looking fonts (k-means on the style vectors, computed once in a worker).
- `src/samples.ts`: the sample font pairs for the ends of the sliders.
- `src/state.ts`: the app state as signals, the browse and shape-search views, the search worker.
- `src/search-worker.ts`: shape search (chamfer distance and skeleton features).
- `src/components/`: the UI.

## Evaluation

`data/eval/` has scripts that compare feature layouts and weight-invariance methods (`eval2.py`, with `scripts/download-weights.mjs` and `embed.mjs --weights`) and render contact sheets (`sheet.mjs`).
